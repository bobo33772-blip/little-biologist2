## 기록 작성 규칙

- 기능 추가·변경, 구조 결정, 외부 서비스 교체처럼 **"왜?"를 설명할 거리가 있는 작업**마다 기록을 1건 추가합니다.
  오타·문구 수정 같은 작은 변경은 기록하지 않거나 관련 기록의 "남은 일"에 한 줄로 덧붙입니다.
- 파일 이름은 `NNN-영문-주제.md`(번호는 001부터 순서대로)로 하고, 위 **기록 목록** 표에 한 줄을 추가합니다.
- 스크린샷 같은 이미지는 `images/NNN-설명.jpg`로 넣습니다(JPEG, 가로 1400px 이하 권장).
- 누가 시작했는지(직접 기획 / 사용자 피드백 / AI 제안 등)를 "계기"에 적어 두면 나중에 맥락을 설명하기 좋습니다.

## 기록 템플릿

```markdown
# NNN. 제목

- 날짜: YYYY-MM-DD
- 분류: 기능 추가 / 개선 / 버그 수정 / 플랫폼 / 인프라 / 문서 중 하나
- 계기: 이 작업을 시작하게 된 이유 (누가, 어떤 문제를 보고)
- 관련 커밋: `abc1234` 커밋 제목

## 1. 배경
어떤 문제가 있었나. 사용자에게 어떤 불편이 있었나.

## 2. 검토한 선택지와 결정
| 선택지 | 장점 | 단점 |
|---|---|---|
결정: 무엇을 골랐고 **왜** 골랐는지.

## 3. 구현
무엇을 어떻게 바꿨나. 핵심 파일과 설계 포인트.

## 4. 검증
어떻게 확인했나. 결과(숫자, 스크린샷, 테스트).

## 5. 한계와 남은 일
아직 안 된 것, 알려진 문제, 다음 단계.

## 6. 포트폴리오 포인트
이 작업으로 보여줄 수 있는 역량을 한두 줄로.
```
