# 002. 서비스 소개 README와 개발 기록 체계

- 날짜: 2026-10-04
- 분류: 문서
- 계기: 포트폴리오로 정리하려니 두 가지가 부족했다.
  - GitHub README만 봐서는 리틀 바이올로지스트가 무슨 서비스인지 알기 어려웠다.
  - 기능을 왜 그렇게 만들었는지 남아 있는 기록이 없었다.
- 관련 커밋: `7e27bd9` docs: rewrite README as a service overview and start a portfolio devlog

## 1. 배경

기존 README는 초기 "프론트엔드 네비게이션 뼈대" 설명 그대로였고, 실제 코드와 어긋난 부분이 있었다.

- "백엔드 API 연동 안 됨"이라고 적혀 있었다. 실제로는 Supabase, iNaturalist, OpenAI, CLIP이 모두 연결돼 있다.
- 도감이 "80종"이라고 적혀 있었다. 실제 데이터(`INSECT_SPECIES`)는 79종이다.
- 서비스의 정체성(대상, 핵심 아이디어, 게임 흐름)이 빠져 있었다.

## 2. 검토한 선택지와 결정

| 선택지 | 판단 |
|---|---|
| 기존 README에 문단만 덧붙이기 | 어긋난 설명이 남아서 오히려 혼란을 준다 |
| **README를 서비스 소개 중심으로 새로 쓰기** ✅ | 처음 보는 사람(면접관·팀원)이 1분 안에 서비스를 이해할 수 있다 |
| 개발 기록을 한 파일에 계속 이어 쓰기 | 길어지면 기능별로 꺼내 쓰기 어렵다 |
| **기능마다 파일 하나 + 색인 표** ✅ | 포트폴리오에 항목별로 바로 옮길 수 있고, 같은 템플릿이라 비교하기 쉽다 |

- 앞으로 AI 도우미와 작업할 때도 기록이 빠지지 않도록 규칙을 남긴다.
  - 저장소 루트의 `CLAUDE.md`에 개발 기록 규칙을 적었다. 이 파일은 Claude Code가 작업을 시작할 때 자동으로 읽는다.

## 3. 구현

- **README.md**
  - 한 줄 소개와 링크(웹 플레이·안드로이드 앱·개발 기록·설치 가이드)
  - 서비스 소개(대상·핵심 아이디어·안전 원칙)와 플레이 흐름도(mermaid)
  - 주요 기능 표, AI 활용 표, 기술 구성도
  - 실행 방법, 폴더 구조, 다음 계획
  - 숫자는 모두 코드에서 다시 확인했다. 예: 79종과 서식지별 종 수, 미션 82개(일일 후보 12·주간 10·업적 30·칭호 30), 퀴즈 보상.
- **스크린샷**
  - 실제 빌드를 Playwright로 태블릿 가로(1180×820)로 띄워 찍었다. 서버 응답은 빈 진행도로 대체했다.
  - 저장 위치: `docs/images/`
- **개발 기록**
  - `docs/devlog/README.md`에 색인, 작성 규칙, 템플릿을 넣었다.
  - git 기록과 SETUP.md를 바탕으로 웹 버전 주요 이력을 요약했다.
- **CLAUDE.md**: 프로젝트 요약, 명령어, 코드 규칙(`apiUrl()` 사용, 웹/앱 분기 원칙), 개발 기록 규칙을 담았다.
- **SETUP.md**: 7번 "안드로이드 앱 빌드"를 추가했다(APK 받기, Android Studio 빌드, 웹과 앱의 차이, 설정 체크리스트, iOS).

## 4. 검증

- README에 적은 기능 설명과 숫자는 해당 코드에서 직접 확인했다.
  - `src/data/*.js`
  - `Exploration.jsx`, `Quiz.jsx`, `GachaModal.jsx`
  - `representativeCharacter.js`, `server/index.js`
- 문서 안 링크(개발 기록, SETUP 앵커, 이미지 경로)가 실제 파일과 제목을 가리키는지 확인했다.
