# 005. 아이폰 홈 화면 앱: 가로로 돌리면 화면이 아래로 밀리는 문제

- 날짜: 2026-10-06
- 분류: 버그 수정
- 계기
  - 사용자가 아이폰 홈 화면 앱의 가로 화면 스크린샷을 보내며 "잘 맞춰 달라"고 요청했다.
  - [004](004-fill-landscape-screen.md)는 아직 main에 합치기 전이라, 스크린샷은 수정 전 화면이다.
- 관련 커밋: (커밋 후 채움)

## 1. 배경

스크린샷(2000×924px로 줄어든 이미지)에서 바깥 빈 띠의 크기를 픽셀 단위로 쟀다.

| 위치 | 빈 띠 |
|---|---|
| 왼쪽 | 121px |
| 오른쪽 | 122px |
| 위 | 122px |
| 아래 | 0px. 대신 아래 메뉴가 잘려 이름(탐험·도감…)이 안 보인다 |

- 빈 띠 색은 `#F7F4E9`로 페이지 배경색(`#F8F4E9`)과 거의 같다. 화면 바깥이 아니라 웹 화면 안에서 칠해진 부분으로 보인다.
- 화면 비율(약 2.16:1)로 보면 812×375pt(아이폰 13 mini 등)나 844×390pt(아이폰 12~14 등) 기종이다. 띠 하나는 약 50pt다.
- **양옆 띠**는 004에서 찾은 원인과 같다(`viewport-fit` 기본값). 004가 배포되면 사라진다.
- **위 띠 + 아래 잘림**은 004에서 흉내 내지 못한 새 증상이다.
  - 위가 약 50pt 비고 그만큼 아래가 잘렸다. 화면 전체가 약 50pt 아래로 밀린 모습이다.
  - 이 게임은 홈 화면 앱을 세로로 열면 "가로로 돌려 주세요" 안내가 뜬다([003](003-iphone-home-screen-app.md)). 그래서 거의 항상 **세로로 열고 가로로 돌리게** 된다.
  - 다른 홈 화면 웹 앱에서도 회전과 상태 바 높이가 얽힌 같은 계열의 iOS 버그가 보고됐다.
    - [Victron gui-v2](https://github.com/victronenergy/gui-v2/pull/3280) (iOS 27): 세로→가로→세로로 돌리면 문서가 상태 바 높이만큼 밀린다. `scrollY`는 0인데 `visualViewport.offsetTop`은 59였다. 밀림을 감지하면 `scrollTo(0, 0)`으로 되돌려 해결했다.
    - [Apple 개발자 포럼](https://developer.apple.com/forums/thread/110854) (2018, iOS 12): 세로에서 가로로 돌리면 빈 상태 바가 생기고, 처음부터 가로로 열면 생기지 않는다.

## 2. 검토한 선택지와 결정

| 선택지 | 장점 | 단점 |
|---|---|---|
| 상태 바 스타일을 `black-translucent`로 바꾸기 | 웹 화면이 항상 상태 바 자리까지 덮는다 | iOS 26에서 이 조합은 화면 높이가 상태 바만큼 짧게 계산되는 버그(WebKit 301108)가 있다. 그리고 이 설정은 홈 화면에 추가할 때만 읽혀서, 바꾸면 앱을 지우고 다시 추가해야 한다([참고](https://github.com/nckrtl/orbit/pull/754)) |
| **회전 뒤 밀림을 감지해 되돌리기 + 가로 폰에서 남은 위쪽 안전 영역 값 무시** ✅ | 다시 설치할 필요가 없다. 같은 버그를 겪은 앱(Victron)이 쓴 방법이다. 홈 화면 앱에서만 동작해서 브라우저 탭은 그대로다 | 실제 아이폰에서만 생기는 버그라, 여기서는 흉내로만 확인할 수 있다 |
| 처음부터 가로로 들고 열라고 안내 | 코드 수정이 없다 | 아이에게 매번 순서를 지키게 하기 어렵다 |

**결정: 두 번째.** 상태 바 스타일은 지금처럼 `default`로 둔다.

## 3. 구현

### 3-1. 밀림 되돌리기 — `src/components/common/StandaloneViewportFix.jsx`

- 홈 화면 웹 앱에서만 켠다(`isStandaloneWebApp`).
- 언제 확인하나
  - 회전·크기 변경 이벤트(`orientationchange`, `resize`, `visualViewport`의 `resize`, `screen.orientation`의 `change`)가 오면 확인한다.
  - iOS가 회전이 끝난 뒤 크기를 다시 정하는 경우가 있어서, 0·250·800ms 뒤에 세 번 확인한다.
- "밀렸다"고 보는 경우
  - `visualViewport.offsetTop`·`offsetLeft`가 0이 아니다.
  - 문서 맨 위의 화면상 위치가 `-scrollY`와 다르다. 정상이라면 항상 같다.
  - `scrollY`가 음수다.
- 건드리지 않는 경우
  - 손가락으로 확대한 상태(`visualViewport.scale`이 1이 아님)
  - 키보드가 열린 상태(보이는 높이가 150px 이상 줄어듦)
- 되돌리는 방법: 스크롤 위치를 다시 지정한다(`scrollTo`).
  - 도감처럼 스크롤되는 화면은 보던 위치를 유지한다.
  - 음수로 당겨진 경우만 0으로 되돌린다.

### 3-2. 가로 폰에서 남은 위쪽 안전 영역 값 무시 — `src/index.css`

- 아이폰은 가로로 들면 상태 바를 숨긴다. 그래서 위쪽 안전 영역은 원래 0이어야 한다.
- 그런데 회전 뒤에 세로 때 값(상태 바 높이)이 남으면, 004에서 넣은 위쪽 여백 때문에 목장 위쪽 UI가 그만큼 내려간다.
- 그래서 **아이폰 홈 화면 앱 + 가로 + 높이 500px 이하**일 때는 `--safe-top`을 0으로 둔다.
  - 표시용 클래스 `ios-home-screen-app`은 `StandaloneViewportFix`가 붙인다(`navigator.standalone` 기준, `platform.js`의 `isIosHomeScreenApp`).
  - 안드로이드 앱(Capacitor가 주는 값), 브라우저 탭, 세로 화면, 태블릿은 그대로다.

### 3-3. 로그인 카드 크기 다시 계산 — `src/pages/auth/authVisuals.jsx`

- 회전 직후에는 화면 크기·안전 영역 값이 늦게 바뀌는 경우가 있다.
- 그래서 회전 500ms 뒤에 카드 크기를 한 번 더 계산한다.

## 4. 검증

Playwright(Chromium 141)로 홈 화면 앱 모드(`navigator.standalone = true`)를 흉내 내 확인했다.
- iOS의 실제 밀림 상태는 Chromium에서 만들 수 없다.
- 그래서 문서의 화면상 위치와 `visualViewport` 값을 바꿔 "밀린 상태"를 흉내 내고, `scrollTo`가 불리는지 기록했다.

| 상황 | 결과 |
|---|---|
| 평소 목장에서 회전 이벤트 | 아무것도 하지 않음(`scrollTo` 0회) |
| 문서가 50px 아래로 밀린 상태 + 회전 | 되돌림 실행 |
| 문서가 59px 위로 밀린 상태(Victron 사례) + 크기 변경 | 되돌림 실행 |
| 키보드 열림(`offsetTop` 100) | 건드리지 않음 |
| 키보드를 닫았는데 `offsetTop`이 남음 | 되돌림 실행 |
| 손가락 확대(`scale` 1.6) | 건드리지 않음 |
| 가방 화면을 600px 스크롤한 뒤 회전 | 건드리지 않음, 위치 600px 유지 |
| 같은 화면 + 40px 밀림 | 되돌리면서 위치 600px 유지 |
| 브라우저 탭 + 밀림 | 동작하지 않음(웹 동작 그대로) |
| 아이폰 홈 화면 앱·가로 + 위쪽 안전 영역 50이 남음 | `--safe-top` 0, 프로필 카드가 원래 자리(위 12px) |
| 아이폰 홈 화면 앱·세로 + 위쪽 59 | `--safe-top` 59 (세로는 그대로) |
| 004 점검 다시 실행 | 4개 기종 노치·홈 바 겹침 0건, 노치 없는 화면 32건 버튼 위치 동일, 첫 주소(/)부터 시작 흐름 정상 |
| 린트·빌드 | 새로 만들거나 바꾼 파일 ESLint 오류 0건, `vite build` 통과 |

## 5. 한계와 남은 일

- [ ] **실제 아이폰 확인 (가장 중요)**: 이 버그는 실제 iOS에서만 생긴다. 배포 뒤 아래를 확인한다.
  - 홈 화면 앱을 세로로 열고 가로로 돌렸을 때 위 빈 띠와 아래 잘림이 없는지
  - 가로로 연 채 다시 열었을 때도 같은지
- [ ] **그래도 위에 띠가 남으면**: 문서가 밀린 게 아니라 iOS가 웹 화면 자체를 상태 바 아래에 두는 경우일 수 있다. 이 경우는 페이지에서 감지할 수 없다.
  - 그때는 상태 바 스타일을 `black-translucent`로 바꾸고 홈 화면 앱을 다시 추가하는 방법을 검토한다. 위의 WebKit 301108 버그를 함께 따져야 한다.
- [ ] **기종·iOS 버전**: 스크린샷 비율로 추정했다. 정확한 기종과 iOS 버전은 확인하지 못했다.

## 6. 포트폴리오 포인트

- 사용자 스크린샷을 픽셀 단위로 재서, 이미 고친 원인(양옆 띠)과 새 원인(위 띠 + 아래 잘림)을 구분했다.
- 실기기 없이 재현할 수 없는 버그를 다른 프로젝트의 보고(증상, 측정값, 해결 방법)와 맞춰 보며 원인을 좁혔다.
- 보정 코드에는 안전장치를 두었다. 확대, 키보드, 스크롤 화면, 브라우저 탭에서는 동작하지 않거나 보던 위치를 지킨다.
- 흉내로 확인한 것과 실기기로 확인해야 할 것을 나눠 기록했다.
